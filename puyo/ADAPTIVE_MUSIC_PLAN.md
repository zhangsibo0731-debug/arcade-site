# 噗呦噗呦 · 自适应背景音乐实施计划

更新日期：2026-09-15
状态：B0/B1 已完成；B2 已接入，等待手机实机试听
定位：月夜电子街机 × 轻快果冻感 × 随局势递进的自适应音乐
范围：经典模式与挑战模式共用一套主题，通过音乐分层体现模式、压力、连锁和特殊 Stage；不引入第三方版权音乐。

## 1. 产品目标

背景音乐需要做到：

- 长时间游玩不疲劳，不抢占落子判断所需的注意力。
- 与紫色月夜、霓虹、果冻弹性的视觉风格一致。
- 经典模式更轻松，挑战模式更有推动感，但听起来仍是同一首主题。
- 棋盘堆高、干扰临近和特殊 Stage 时逐渐紧张，而不是突然切歌。
- 连锁音效属于音乐的一部分，2～5 Chain 的递进自然落在背景音乐调性内。
- 暂停、切后台、恢复和静音时没有爆音、重叠播放或节拍错乱。

目标体验：

```text
安静观察 NEXT
→ 轻快搭建
→ 压力逐渐增强
→ 连锁音阶向上攀升
→ 高连锁短暂进入高潮
→ 回落到基础循环
```

## 2. 音乐风格

### 2.1 核心参数

- 速度：建议先以 `110 BPM` 试做，允许在 `106～114 BPM` 内实机微调。
- 拍号：`4/4`。
- 调式：优先使用明亮但略带夜色的五声音阶或自然小调，避免过度阴沉。
- 循环长度：首版 `16 小节`，约 35 秒；成熟后可扩展至 `24～32 小节`。
- 音色：圆润合成贝斯、玻璃/水滴短音、柔和方波主旋律、轻电子鼓和空气感铺底。
- 动态：整体响度必须低于消除、落地、警告和 Chain 音效。

### 2.2 不采用的方向

- 不做儿童儿歌式旋律。
- 不使用持续高频、尖锐方波或密集旋律。
- 不直接模仿商业游戏的旋律、和声或标志性音色。
- 不使用无法确认授权的网络音乐。
- 不让音乐速度直接随 Level 无限加快，避免影响操作判断。

## 3. 自适应音乐结构

音乐采用两条同 BPM、同调性、同长度的完整 WAV：普通主题与高压变奏。运行时让两条音轨共享播放位置，在音乐状态变化时交叉淡化，因此既能明显改变气氛，也不会从头重播或中途断拍。

### 3.1 基础层 `base`

始终作为主题骨架：

- 稀疏鼓点。
- 圆润低音。
- 简单和弦脉冲。
- 每 2～4 小节出现一次短旋律回应。

经典模式主要使用基础层，避免持续制造紧迫感。

### 3.2 挑战状态 `challenge`

挑战模式前期仍使用普通主题；进入 Stage 4 后切换至高压变奏。高压变奏：

- 使用更亮、更易辨认的街机主音色。
- 增加回应旋律、切分底鼓和低音八度脉冲。
- 保留原主题、和声、BPM 与小节长度，确保仍属于同一首曲子。

### 3.3 压力层 `pressure`

根据统一压力值平滑混入，压力来源包括：

- 棋盘占用高度。
- 待落干扰数量。
- 干扰距离落下剩余组数。
- 任务剩余组数。
- 特殊 Stage 状态。

第一版压力建议计算为 `0～1`：

```text
棋盘高度      45%
干扰临近程度  30%
待落数量      15%
任务期限      10%
```

长期方案允许压力值微调两条音轨的混合比例，但第一版不按瞬时压力频繁切换，避免音乐来回摆动：

- 经典模式：始终使用普通主题。
- 挑战模式 Stage 1～3：使用普通主题。
- 挑战模式 Stage 4 起：使用高压变奏。
- 特殊 Stage：无论序号均使用高压变奏。
- 切换发生在小节边界，并使用短交叉淡化；暂停、恢复和读档后必须保持正确音轨。

### 3.4 高潮层 `climax`

只在重要瞬间短暂出现：

- 4 Chain 以上。
- 全消。
- 特殊 Stage 完成。
- 刷新本局最高连锁。

高潮层持续 1～2 小节，通过琶音、亮色铺底或附加打击乐增强；不得遮盖连锁报数。结束后按当前压力值回到对应层级。

## 4. 连锁与音乐的结合

当前 Chain 音效需要与背景音乐共用调式和节拍参考。

建议规则：

| 事件 | 音乐反馈 |
|---|---|
| 普通消除 | 保留轻巧短音，不改变音乐层 |
| 2 Chain | 播放主题音阶第一个上行音 |
| 3 Chain | 上行至更明亮音级，加入短促和弦 |
| 4 Chain | 加入一次琶音，并激活高潮层 |
| 5 Chain+ | 继续上行但限制最高音高，避免刺耳 |
| 连锁结束 | 播放与当前和弦相容的收尾音 |
| 全消 | 单独的完整解决和弦，优先级高于普通收尾 |

约束：

- 连锁音效必须立即响应消除，不为等待节拍而产生明显延迟。
- 可将音符吸附到最近的细分拍，但最大延迟建议不超过 `35ms`。
- 背景音乐在 Chain 期间适当降低中高频或音量，为反馈留出空间。
- Stage、强化和契约提示音继续排在连锁总结之后。

## 5. 场景状态

### 菜单

- 可播放极简环境版主题，或保持安静直到首次用户交互。
- 必须遵守移动浏览器的自动播放限制。

### 经典模式

- 基础层为主。
- 高堆叠时只做轻微压力变化。
- 高连锁和全消仍可触发高潮层。

### 挑战模式

- 基础层 + 挑战层。
- 压力值实时影响编配。
- 特殊 Stage 增加独立但克制的节奏色彩。

### 暂停、构筑和选择弹窗

- 不直接停止并重开音乐。
- 使用低通滤波和约 30%～45% 音量，制造“退到背景”的感觉。
- 返回游戏时在 300～500ms 内恢复。

### Game Over

- 主循环快速但平滑淡出。
- 播放 1～2 秒的独立结束句。
- 再来一局时从下一个完整小节或主题开头重新进入。

### 页面隐藏与恢复

- `visibilitychange/pagehide` 时挂起音乐调度并释放未播放节点。
- 返回前台后重新以当前模式和压力启动，不补播离开期间的节拍。

## 6. 设置与存档

现有总声音开关继续保留，并增加独立控制：

- 总声音：控制音乐与音效。
- 背景音乐：单独开关。
- 音乐音量：第一版可只提供低、中、高三级，默认“中”。
- 音效音量：暂时维持现有值，后续根据实机反馈决定是否开放。

建议存档字段：

```js
audioSettings = {
  muted: false,
  musicEnabled: true,
  musicVolume: 0.55
}
```

兼容原则：

- 旧用户没有新字段时默认开启音乐，但首次进入不要突然以高音量播放。
- 原有静音用户升级后继续保持完全静音。
- 设置只存在本机，不进入对局快照，不影响继续上次游戏。

## 7. 技术方案

正式版采用“离线生成 WAV + Web Audio 播放”的结构。曲谱和合成器只在开发期运行，浏览器不下载生成代码。

当前结构：

```text
tools/music/
├── render.js                         # 项目级统一渲染入口
├── synth-renderer.js                 # 通用街机音乐合成器
└── tracks/
    ├── puyo-theme.js                 # 普通主题曲谱
    └── puyo-theme-pressure.js        # 高压变奏配置

puyo/
├── music.js                          # 运行时播放器与状态切换
└── assets/
    ├── puyo-theme-full-v2.wav        # 正式普通主题
    └── puyo-theme-pressure.wav       # 正式高压变奏（B2 接入时落位）
```

现有 `audio.js` 继续负责即时音效和震动；`music.js` 负责 WAV 的加载、循环、同步切换和生命周期。两条音乐轨道必须共用一个 `AudioContext` 与总线。

接口建议：

```js
music.start({ mode, stage, special })
music.setSituation({ mode, stage, special })
music.onChain(chain)
music.onAllClear()
music.setPaused(value)
music.setEnabled(value)
music.setVolume(value)
music.stop()
```

工程约束：

- 音乐模块不直接读取棋盘、DOM 或 localStorage。
- 游戏协调层只传递已经计算好的状态。
- 两条 WAV 解码后复用 `AudioBuffer`，不可随 Stage 重复请求或解码。
- 切换时从相同播放偏移启动目标音轨，并在小节边界交叉淡化。
- 页面隐藏、新游戏和 Game Over 时必须取消旧加载/切换 token。
- 不在 `requestAnimationFrame` 中持续创建音频节点。

### B1：基础音乐接入

**状态：✅ 完成**

- 新增 `music.js` 和独立测试接口。
- 处理首次交互启动、静音、暂停、切后台和恢复。
- 经典模式接入基础层。
- 增加音乐开关和音量设置。

验收：无自动播放报错、无重复音乐、刷新后设置保持一致。

当前进展：已新增独立音乐模块并接入正式页面。音乐在实际游玩开始时启动，暂停或切后台时暂停，结束或返回菜单时停止；声音按钮同时控制即时音效与背景音乐。B2 首步已完成：连锁达到 2/3+ 时提升背景层响度，连锁结束后恢复，作为后续真正动态层的低风险验证。

循环修正：不再依赖曲尾 `setTimeout` 停止并重启，而是根据 `AudioContext.currentTime` 提前排程下一轮；保留终止主音到循环边界，避免尾音被截断和过长空白。暂停期间音频时钟冻结，恢复后继续原有拍点。

音乐性修正：技术无缝后仍发现末句提前在属七和弦上落到 C，与和弦内的 B 形成小二度冲突。末句现改为顺阶回落并停留在 G，最后一拍以轻量 G7 和声托住，进入下一轮 C 和弦与 E 旋律时完成自然解决。

完整曲式：原 12 小节主题重复两遍仅有约 22 秒独立旋律，现扩写为 32 小节、约 58 秒：12 小节 A 段建立并变化主题，8 小节 B 段使用更舒展的新旋律与和声，4 小节桥段主动减层蓄力，最后 8 小节由 A 主题高潮回归并以 G7 衔接循环。

离线交付：项目级 `tools/music/render.js` 调用通用合成器与噗呦曲谱，可重复生成 44.1 kHz、16-bit、双声道 WAV。执行 `node tools/music/render.js puyo-theme` 即可更新正式音频，时长约 58.18 秒。

句尾连续性：V1 在约 7.3、14.5、50.9 秒处让旋律、琶音和踩镲同时停止一整拍，导致呼吸变成断层。V2 将空白缩短为半拍，保留句尾落点音，并让琶音与踩镲延续到最后半拍；低音支撑不变。

运行时方案：正式游戏已从逐音符实时合成切换为加载 `assets/puyo-theme-full-v2.wav`，通过循环 `AudioBufferSourceNode` 播放。暂停/恢复、静音和连锁增益仍由 Web Audio 控制。可编辑乐谱位于 `tools/music/tracks/puyo-theme.js`，仅供项目级离线工具重新导出；正式页面不会下载曲谱或合成器代码。

母带修正：正式 V2 已加入 6ms 首尾边界修整，循环边界采样跳变归零；琶音、踩镲和部分打击乐做轻微立体声展开，主旋律、低音与底鼓保持居中。整体响度维持约 `-15.7 dB RMS / -1.1 dB Peak`。

- 小节边界切换保持播放位置同步，并防止重复切换。

- 4 Chain、全消和最高连锁的高潮触发与去重。
- 页面隐藏后不继续排入新节点。

实机试听：

- 手机外放低音量下仍能听清落地、消除和 Chain。
- 耳机下高频不刺耳、低频不过量。
- 经典模式连续 15 分钟不疲劳。
- 挑战模式压力变化可感知但不突兀。
- 暂停弹窗与强化选择期间音乐明显退后。
- 快速切后台和恢复至少 10 次，无叠音和爆音。

## 10. 风险与回退

- 若程序化音色过于像蜂鸣器，先替换振荡器包络和滤波，不扩大旋律复杂度。
- 若移动端性能不足，减少装饰层与同时发声数量，不降低游戏帧率。
- 若背景音乐容易疲劳，优先增加休止和编配变化，而不是增加更多旋律。
- 若 Web Audio 在部分设备表现不稳定，保留切换为同步 OGG 分层循环的接口。
- 任意阶段出现问题时，音乐模块可整体关闭，现有游戏音效继续独立工作。
