# 数独微信小游戏迁移计划

状态：S1–S5 共享实现完成，S6 自动回归和网页实测通过；手机真机验收、最终模拟器重测及体验版上传尚未完成。2026-10-27。

## 目标与边界

沿用噗呦迁移原则：迁移原版规则，不在微信端重新实现第二套玩法。
先保留原版外观与功能，再处理平台差异；不新增难度、每日挑战、排行榜或商业化功能。
原版浅色纸墨风与儿童版活泼配色应保留，不直接套用噗呦的深色棋盘。
所有改动默认本地保存；提交、推送和微信上传分别取得用户批准。

已确认技术路线：共享玩法核心、展示模型、布局、Canvas 渲染和弹窗，只在平台边缘分别适配。
不再维护一套网页 Canvas 和另一套微信 Canvas。现有 DOM 页面保留为行为/视觉参考和回退，不立即替换默认入口。

## 当前基线（已核对代码）

- `sudoku/game.js` 同时包含算法、状态、DOM、计时及 localStorage。
- 原版：9×9，简单/中等/困难，目标提示数分别为 44/36/30；挖空时验证唯一解。
- 儿童版：4×4（2×2 宫）、6×6（2×3 宫）、9×9（3×3 宫）；使用单空格可解检查及开局补数。
- 注意：儿童 9×9 当前实际也从 `LEVELS.easy.clues=44` 开始再补数，并未使用 `SIZES[9].clues=56`。迁移不得按配置表猜测或偷偷更改。
- 操作：选格、输入、擦除、笔记位掩码、撤销、3 次提示；提示优先当前错误格，否则首个空格。
- 撤销最多 250 步，只回退 board/notes，不恢复提示次数、失误数；重进不保留撤销栈、选中格、笔记模式。
- 反馈：同行/同列/同宫、同数字高亮；重复冲突提示；儿童鼓励语、完成行列宫反馈和胜利彩屑。
- 计分：用时、失误、最佳用时，无积分排行榜。
- 原存档 `sudoku_save_v1`；纪录 `sudoku_best_v1`，键目前为 `size-level`，并未区分原版/儿童版。兼容时保留，是否改分桶另行确认。

## 模块与复用方案

共享源码唯一来源位于 `sudoku/`：

- `rules.js`：配置、出题/解题/计解数、儿童可解与开局补数、宫/行/列集合、冲突检测。
- `game-session.js`：唯一状态机，输入/笔记/擦除/提示/撤销/计时/完成判定；注入随机源，输出状态与语义事件。
- `session-state.js`：序列化与校验，兼容原存档缺省字段；不访问 localStorage 或 wx。
- `presentation.js`：格子给定/用户/选中/同数/同行列宫/冲突状态，数字余量、文案和统计。
- `layout.js`：输入视口、安全区与模式，输出棋盘、数字键、工具栏、弹窗及触区矩形；绘制和命中检测共用这些矩形。
- `renderer.js` / `overlays.js`：同一套 Canvas 界面、色板、笔记绘制、弹窗和儿童反馈，不调用 DOM 或 wx。
- `controller.js`：选格、键盘/指针语义命令、弹窗输入隔离、滚动阈值和场景状态，避免两端控制流程再次分叉。
- `canvas.html` / `web-platform.js`：网页 Canvas 测试入口，适配画布、DPR、键盘/指针、安全区、localStorage 和生命周期。
- 原 `game.js`：先接共享核心，保留 DOM/CSS 回退，不新增两套玩法。Canvas 验收后是否替换网页默认入口，由用户确认。

微信端仅新增适配层：

- `src/sudoku-game.js`：薄场景包装，实例化共享控制器和渲染器，不重复编写规则、布局或弹窗。
- `src/sudoku-platform.js`：微信触摸、wx 存储、生命周期、DPR 与安全区；复用现有平台基础能力。
- 新模块保持简单 JS 与 Canvas 2D 公共子集，不引入浏览器专用字体/滤镜，也不为本次迁移增加重型引擎。
- 同步脚本将共享模块复制到 `vendor/sudoku/`；禁止直接编辑 vendor，测试检查逐字一致。

数独运行入口必须独立于 `PuyoGame`：先抽出轻量游戏厅/场景路由，再接数独。
每个场景使用统一 enter/leave/update/draw/touch 接口；触控监听与生命周期由根入口分发，避免重复注册。
不可为了接数独而复制噗呦控制器，或持续把数独逻辑塞进 `puyo-game.js`。
